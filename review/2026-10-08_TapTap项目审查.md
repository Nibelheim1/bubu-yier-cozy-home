# 《布布一二 · 好日子小屋》TapTap 项目审查

审查日期：2026-10-08。对象：当前目录的 v1.0.0 源码、现有 dist/release、设计文档与既有 QA 记录。本轮只审阅；未修改源码、素材、剧情原稿，也未上传或发布游戏。

## 产品判断

**这是核心闭环完整、题材一致的陪伴式轻合成单机作品。继续打磨有价值；当前最需要改善的是角色行动、后半程的新鲜感和终局回报。** 现有证据支持“六章可通关的单机游戏”，尚不足以支持“能长期留住玩家的经营产品”或“已经达到 TapTap 发行验收条件”。

建议定位：和布布一二整理共同的小屋，通过合成完成小愿望、收集生活回忆。主打放松、相处与可见的家居变化。现阶段更适合把一个短篇陪伴体验做得让人记得住，再根据真人反馈决定是否扩成长线产品。

| 维度 | 本轮判断 | 依据与限制 |
|---|---|---|
| 核心闭环 | 成立，值得保留 | 生产→二合→交付→心愿星→布置→新任务；6章24项修缮 |
| 布布一二题材结合 | 文案与生活目标结合较好 | 扶桌脚、分享蛋糕、纸鲸、量幼苗、调灯等具体互动；不能据原创支线认定官方 Canon 一致 |
| 放松与容错 | 合理 | 免费茶歇、轻松模式、仓库、拆分、撤销；金币花光不会永久卡住主线 |
| 角色与演出 | 需要重点提升 | 家园固定角色站位，少量随机闲聊，剧情多为立绘对话；终章聚会没有对应场景 |
| 后期与留存 | 有系统入口，缺少持续目标 | 邻里和每日可以循环，但没有新增来客关系、故事和永久家居回报 |
| 手机操作 | 已有适配，尚未完成真实验收 | 既有小屏截图布局可读；本轮现场试玩被浏览器权限故障阻止，真实触控与宿主未验证 |
| TapTap 发行准备 | 需单独核实 | 包内没有授权证明、平台状态和真实宿主报告；平台能力不是全部必须接入 |

## 值得保留的设计

1. **第一轮回报有实际意义。** 第一次合成解开尘封，交付后让玩家亲手铺门垫；改造把抽象奖励变成“这是两只熊的家”。不要把这一轮改成连续弹窗领奖。
2. **角色并非只存在于头像。** 布布照顾具体事情，一二也会回应、分享和保留纪念。两人的关系基本通过相处表现出来，题材与材料链也一致。应继续发展这些具体行为，而不是增加泛化的甜言蜜语。
3. **主线和便利经济分开。** 心愿星用于对应布置，金币用于便利系统；不需要通过付费或强制等待挽救错误消费。很适合这个放松题材。
4. **视觉主题统一。** 原生查看既有教程、通关小屋与 360×640 截图后，奶油底色、棕色描边、绿色按钮和具体物品轮廓基本协调。继续保留现有主题，优先整理构图与动作。
5. **项目诚实说明验证边界。** README 与 QA 文档没有把内存存储、模拟时间或桌面视口包装成真实云存档、真人时长和真机验收。这一点应保留到后续发布说明。

## 先修的确定缺陷

### P2：邻里委托的提示指向错误材料

`hint()`只考虑当前主线，不考虑邻里委托。通关后没有可合成对时默认建议生产清洁材料；界面调用时也没有传入当前委托页签。

本轮最小复核：加载已有通关状态，通过公开刷新动作得到工具与绘画需求的两张邻里订单，棋盘空位35；提示仍返回 `produce clean`。这是可复现的功能错误，尤其影响通关后的默认继续玩法。

修复：提示接收当前订单目标；邻里页签和通关后优先提示能交付的邻里订单，否则指导生产真实缺少的来源。

证据：[engine.mjs:244](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/engine.mjs:244>)、[ui.mjs:293](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/ui.mjs:293>)。

### P2：第五章回忆的睡觉角色配反

回忆写“一二已经靠着软垫睡着了，布布把灯调暗”，姿势配置却是 `bubu-sleep` 与 `yier-shy`；场景又把 `yier-shy` 映射为 `yier-turn`。手帐与回忆弹层使用这组配置，文案和图像角色相反。

修复：补一二休息姿势与布布调灯/陪伴姿势；如果决定让布布睡觉，必须同步改对应叙事。建议保留原本“一二睡，布布照顾”的情绪目标。

证据：[data.mjs:19](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/data.mjs:19>)、[ui.mjs:182](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/ui.mjs:182>)。这是本轮源码确定的配置冲突，未现场重开该回忆验证渲染。

### P2：大量囤积礼物后，章节奖励产生无法重新载入的存档

购买补给允许待领队列达到1000件，章节结束却直接追加2件，存档校验又要求不超过1000件。规则动作都成功，但游戏自己的导出文件无法重新导入。

本轮复现：通过677次公开规则动作、虚拟推进日期，构造 `stage=3,pending=1000`；交付并布置第4项后变成 `stage=4,pending=1002`，导出再校验报“pending 内容无效”。未注入金币或物品。

触发需要长期大量囤包，普通首轮很难遇到；但保存实现会写入无效状态，之后的状态变化还可能将无效状态写入备份，造成重新打开时丢进度。**已复现的是规则溢出与自身导出不可导入；主档、备份同时失效的后果由代码推导，未做浏览器完整重载复核。**

修复：统一所有礼物入队与容量规则，给章节奖励预留容量或提供不会丢奖励的溢出存放；保存前拒绝以无效状态覆盖有效档。只需补一个“队列接近上限→完成章节→保存重载”的针对性回归。

证据：[engine.mjs:150](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/engine.mjs:150>)、[engine.mjs:203](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/engine.mjs:203>)、[engine.mjs:281](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/engine.mjs:281>)、[ui.mjs:58](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/ui.mjs:58>)。

## 最影响产品吸引力的缺口

### 新工作台首单被赠礼跳过

第4、8、12项改造先解锁新来源，再赠送该来源的两件二阶物品；第5、9、13项任务分别只需要一件该来源二阶。既有合法通关记录中，这三项都是0生产、0合成。

玩家得到小烤箱、画画箱、园艺篮后，可以直接领材料、交付、布置，没机会通过任务体验新来源的第一次制作。这是确定的设计行为；是否导致流失需要真人测试。

建议将这三次章奖改成前一链材料，或新链的一阶材料，再让玩家亲手完成一轮生产/合成。保留赠礼的温柔感，同时让“解锁”成为一次可记住的操作。

证据：[engine.mjs:146](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/engine.mjs:146>)、[data.mjs:35](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/data.mjs:35>)、[campaign-full.json:60](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/qa/campaign-full.json:60>)。

### 后半程增加的主要是数量，末章劳动与回报不匹配

六章需求折算为一阶材料价值分别为14、34、38、46、68、176；末章占总376的46.8%。这是配方价值统计，**不是实际生产次数或真人时长**。全部来源在第12处解锁，全部格子在第14处打开，后面10次改造没有新增来源或棋盘规则。

末章的主题是把好日子分享给别人，文案写请客、门前野餐和第一次庭院聚会，实际终局仍是同一室内背景、家具和两只主角，没有对应来客或门外场景。玩家承担了更大的制作量，得到的却还是相似的布置与对话模板。

建议优先兑现末章：保留24项主线，将最后两单设计成有中间画面回报的聚会准备；完成后给独有聚会画面和短演出。每次合材料都应更接近“客人来了”，而不是只接近计数达标。

证据：[data.mjs:51](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/data.mjs:51>)、[ui.mjs:179](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/ui.mjs:179>)、[通关小屋截图](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/qa/17-complete-home.png>)。

### 陪伴感主要通过文案传递，角色缺少行动

家园默认固定站位，点击主要从六句闲聊随机抽取；惊讶、害羞等表现还被映射到普通站姿或转身。角色有相处细节，但玩家很少亲眼看到这些细节发生。

建议先制作两三个可重复使用的关键动作：一起踩门垫、偷尝蛋糕、布布扶纸鲸、一二量幼苗、调灯盖毯、迎接来客。动作要与玩家刚完成的事情对应。章节可加一个温和的小麻烦，形成“准备→出错→互相补位→实现”，不需要反派或强虐剧情。

证据：[HOME_CHAT](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/data.mjs:72>)、[场景姿势](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/ui.mjs:182>)、[剧情渲染](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/ui.mjs:277>)。

### 邻里与每日提供重复操作，没有提供新的期待

邻里订单是随机需求与五组泛用文字，头像仍是布布或一二；每日目标是合成15次、交付3单、生产25件。奖励继续提供金币、体力和经验，却不带来新关系、回忆或永久家居变化。图鉴补齐后，玩家的下一目标变弱。

我的产品推断：这能维持“还有按钮可点”，很难单独维持“明天我想再打开”。建议先做一位有连续三段请求的原创来客，用现有订单承载他的到访；每次完成2–3单得到一张新回忆和一个永久可见的小变化。明确是单机故事来客，不冒充真实在线邻居，也不擅自宣称新角色是官方 IP 配角。

证据：[每日与邻里数据](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/data.mjs:64>)、[邻里生成](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/engine.mjs:111>)、[订单头像](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/src/ui.mjs:126>)。

## 美术、手机与技术评价

从既有截图看，后期画架、灯、座椅、地毯和野餐垫重叠较多，中央角色活动区被压缩，统一透视也还可以改善。建议先整理最终构图，将墙面、桌面、地面物件分层，给两只熊留清晰的相处区域。当前布置点固定、主要选择两种配色，宣传宜称“改造小屋、选择配色”，不宜承诺任意摆放家具。

小屏棋盘保留七行和紧凑订单是正确方向；细节栏动作按钮只有约27–29 CSS像素宽，部分库存与说明文字7–9px，误触与可读性仍需真机判断。建议优先确认常用收纳、撤销、出售和触摸取消的手感，扩大常用动作命中区域，低频操作可收进面板。不要为了塞入所有按钮继续缩字。

静态部署素材共103个、约4.43MB；其中音乐WAV约1.09MB。启动逻辑等待全部102张图像成功载入后才展示入口。这个实现可以作为首屏加载的观察点，但本轮没有设备基准，不据此判断加载慢或掉帧，也不建议为了优化仪式感全面改格式。实际宿主出现问题后，再按测量结果做章节加载或资源优化。

## TapTap 的定位与发行建议

本项目是纯 H5 静态包。平台形态、目标 App 和包体应单独核实，不能套用其他布布一二项目的 App ID 或线上状态。TapTap 当前官方说明将纯 H5、WebGL 小游戏、APK/PC 和制造版本分为不同接入路径；建议沿 H5 路线做真实宿主预览和小范围玩家测试。[TapTap 官方说明](https://developer.taptap.cn/agents/)

包内明确不授予布布一二商业许可，也没有附授权证明。这不证明用户在包外没有授权；公开发行前应核对实际授权文件的适用范围。角色参考图与自制素材说明不能代替授权材料。[项目权利说明](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home/LICENSE-NOTICE.md:7>)

平台登录、排行榜、广告和云存档不应被当成必须一次补齐的功能清单。对这款题材，排行榜的价值很弱；广告也不应靠收紧现有体力迫使观看。更直接的发布前事项是：真实宿主能打开、完成操作、切后台后恢复、关闭重开仍保留进度，拍照与文件导出有可用结果。若之后成为需要多日投入的产品，云存档的优先级才会上升；H5 可采用官方云存档能力，真实同步完成后才能称作已支持。[TapTap 云存档指南](https://developer.taptap.cn/minigameapidoc/dev/tutorial/open-capabilities/cloud-save-tutorial/)

商店页建议用“空屋→改造后小屋”的真实对比作为第一张截图，第二张展现两只熊的具体互动，第三张展示合成与回忆。简介如实写单机、六章主线、24次改造、36种物品；不要写真实好友联机、任意家具摆放或无限剧情。这里是编辑建议，不是已经测试过的转化结论。

## 收敛后的下一版目标

**主目标：让玩家记住一个相处瞬间，并明确期待下一次来访。** 建议用“小屋来客”作为一次小迭代，复用现有棋盘、货币和邻里系统。

顺序：先修提示、回忆姿势和礼物容量；恢复三次新来源的首次制作；再兑现终章聚会，并制作三次有连续关系的邻里来访。新奖励用回忆和永久小屋变化承载，暂不增加更多合成链、多货币和排行榜。

反馈检查点：邀请约20名目标玩家真实试玩，分开记录新手完成、后期中断、通关后目标和次日自愿回访。20人只能帮助发现反复出现的体验问题，不能当作可靠商业留存估计。可先用以下观察口径：

- 无人解释时，玩家能否走完首次合成→交付→门垫，并亲手制作首个新来源物品。
- 第六章大单是否出现集中中断，玩家能否说出聚会准备发生了什么变化。
- 玩家能否讲出一件具体的布布一二相处细节，而不只是“两个熊很可爱”。
- 通关后是否能说出下一位来客与想得到的回忆；次日回来是否因为想继续这个事件。
- 真实设备上的关闭重开、切后台与操作手感是否稳定。

完成定义：确定缺陷修复；新来源有实际制作；终章有与文案对应的聚会回报；三段来访形成明确新目标；完成相称真机/宿主验收与小规模试玩记录。届时再决定扩内容或调整经营深度。
