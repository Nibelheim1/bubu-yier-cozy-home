日期：2026-10-08。工作标题：**小栗来坐坐**。版本号1.2.0与工作标题均为本方案建议，当前游戏仍是1.1.0。本文件是待实施的修改方案，不是实现记录、留存结果或发布完成证明。

实施补充约束（用户最新指示）：所有人物使用权威角色卡的平面插画风格，包括两熊与原创小栗。纯色填充、清晰轮廓，禁止立体体积光、渐变高光和3D人物渲染；场景与物件沿用现有方向。实际实现和验证状态以本目录本版验收记录为准。

小栗补充裁决：用户要求重新设计，不参考布布。小栗使用独立松鼠角色卡，尖长耳、窄脸与门牙、纤细身体、蓬松长尾、灰蓝与奶油色配芥黄领巾；不用两熊的圆脸、短圆身体和圆形腮红。小栗单独素材仅引用自己的新卡，两熊素材仍同时引用两张权威熊卡。废弃小栗卡与动作只作历史素材留在art，不进入运行包。

**本版主目标：玩家用合成物安排一段不同的小日子，亲手促成布布一二的协作，并在家园留下自己的选择。**

一场庭院首访负责兑现终章；同一套可重玩茶会负责验证重复游玩的动力。v1.2做到这两个相连的闭环，并补齐评审中的正常体验缺陷。它不承诺已经解决数月留存。

**F01：让日常跟家园真实进度一致。**

地区浏览继续从早期开放；可做的小事与实际生活条件对应：

| 区域 | 实物尚未准备好 | 条件达到后的活动 | 新回忆的生活条件 |
|---|---|---|---|
| 小屋 | 整理窗边、找一个能歇脚的位置 | 第7项完成后吹凉茶、分饼干 | 已准备两只杯子，且累计陪伴达到3天 |
| 花园 | 扫落叶、选择种植位置 | 第13项完成后扶苗浇水 | 已认领幼苗，且累计陪伴达到3天 |
| 庭院 | 整理门口、留出待客位置 | 第23项完成后摆茶点；小栗实际到访后才说“朋友来了” | 已做出分享的茶点，且累计陪伴达到3天 |

每天每区一次、8金币与5体力继续沿用。天数累计而非连续签到，跳过一天保留进度。新玩家早期满3次但尚未达到生活条件时，手帐同时显示两个条件；达成对应装修后可收好回忆，无须额外等待一天。

新增独立的“回忆已解锁”记录。迁移时，旧档中累计达到3天的回忆直接保留解锁，不依据新条件锁回。新解锁在装修推进或日常完成后统一检查，不由弹层显示决定。原有日常奖励不会因为解锁、回放或迁移再发一次。

**F02/F03：目标看得懂，新工作台亲手用过。**

补给包保持65金币、三件一级加一件二级的内容结构。购买前展示：服务的具体目标、来源、四件物品名称/等级/数量、价格和“待领礼物”领取位置。目标可以是当前主线的本阶段、某张邻里委托或当前茶会方案。多来源需求由玩家选择仍缺材料的来源。

确认时重新核对目标。委托已刷新、主线已推进或茶会已结束时，旧预览失效并刷新；取消不扣币。目标已备齐时说明原因，不自动切换另一来源。通关默认提供明确的邻里/茶会目标。满盘与满待领队列继续沿用现有规则，不另建补给背包。

新来源教学覆盖修理箱、小烤箱、泡茶台、画画箱、园艺篮。第一笔涉及新来源的主线突出生产器，让玩家成功取出一次材料，再继续合成与交付。原需求、赠礼与物品ID不变，产出仍按原规则；重点补第5/9/13单可被章奖省去生产的问题。教学不会多扣额外材料。

迁移旧档时，已解锁来源视为已认识；尚未开放来源在未来使用新教学。关闭说明不算生产成功。来源按钮和合成路线可随时重看。

**F04/F05：终章保留24项，用准备过程兑现分享主题。**

仅集中调整第21—24项的场景内容与交付呈现，其余故事保留，以小范围精修补足对应动作。小栗设定为住在巷口、喜欢明信片与花草茶的松鼠邻居，是本游戏原创支线角色；布布一二继续是主角。

- 第21项“写一张小小邀请”：一二选邀请语，布布把纸条放好；小栗回信明确愿意来，并说会带一件路上发现的小东西。小旗仍是该项正式装修。
- 第22项“把春天铺到门外”：两熊一起确认树荫位置，布置野餐垫。保持原材料和正式装修，不插入匿名客人已经到场的文字。
- 第23项“做一桌可以分享的甜”：分成点心塔上桌与双人茶盘到位两个准备阶段。一二摆点心，布布拿稳茶盘。
- 第24项“好日子小屋，开门啦”：分成花架、纪念画/手作与最后蛋糕三步准备。正式布置完成后，小栗从入口走到招待位置，一二摆杯、布布端茶，两熊完成交接，小栗接到杯子再回应。

| 正式主线 | 分阶段需求 | 配方价值与奖励边界 |
|---|---|---|
| 第23项，内部索引22 | 点心塔 `bake-6×1` → 茶盘 `tea-5×1` | 总一阶价值仍为32+16=48；原金币/体力/经验/一颗心愿星只在末阶段发放一次 |
| 第24项，内部索引23 | 花架 `garden-6×1` → 手作 `craft-6×1` → 蛋糕 `bake-5×1` | 总一阶价值仍为32+32+16=80；同样只发一次原订单奖励 |

界面同时显示当前阶段和全部剩余需求，允许提前准备。每阶段只扣自己的物品，立即保存并把准备物放到现场；这不是新增一次正式装修。最后仍选择配色、执行原装修动作，stage总数和心愿星职责保持不变。阶段交付同时校验预期任务编号和准备阶段，避免连续点击意外扣下一阶段材料。

末阶段奖励按整张原订单计算，不能只算最后一份材料：第23项基础奖励为162金币、4体力、26经验、1颗心愿星；第24项为258金币、4体力、36经验、1颗心愿星。经验升级与正式装修的奖励另沿用原规则。计算依据为当前主线奖励与整单经验公式：[data.mjs](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home-v1.1/src/data.mjs:55>)、[engine.mjs](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home-v1.1/src/engine.mjs:159>)。

本版首先增加回报密度，不直接重调末章总需求。实施后的真人试玩若仍集中在高阶准备中断，再按真实记录单独调整，不能用虚拟求解时间当真人时长。

小栗到访后留下一封提及玩家准备内容的回信，并给出下一次约定。既有聚会原图继续保留为六章纪念；首访的动态场景和三角色合照是新增回报，不能用该静态图替代到访演出。

旧通关玩家获得新茶会入口和“邀请小栗来坐坐”的补充事件，沿用已经布置好的家园，不补发主线、章奖或原图鉴奖励。已交付但未布置的第23/24项旧档视为准备阶段全部完成，保留原心愿星，直接允许布置。

首访规则状态为 `locked/available/arrived`。新档完成第24项正式布置、旧通关档迁移后进入 `available`；确认迎接时一次记录 `arrived` 并保存，再播放首访演出。跳过演出仍展示到访结果，中断重载可补看；关闭尚未开始的邀请不算到访。小栗是否参加新茶会只读取 `arrived`，不依赖动画播放结束回调。此前已取得的两熊茶会回忆继续保留原参与者。

**F06：一套可重玩的茶会，而非再造一个合成游戏。**

开入口的正式条件建议为第13项完成、新来源教学已经走过：全部茶会所需来源已开放，花园也确有幼苗。通关前是“两熊的小茶会”，只有布布一二；小栗在终章正式到访后才加入后续茶会。这样不会出现先接待客人、再写第一次邀请的顺序冲突。

一次茶会的玩家路径为：

**查看本次小状况 → 选择暖心茶点或花园小聚 → 用现有工作台准备 → 确认交付 → 操作两熊完成协作 → 查看回应与纪念物 → 保留或更换家园摆法。**

三种状况按完成轮次循环，开始前可见：晴日来坐坐、想留一份纪念、今天有点风。状况改变需要准备什么以及现场怎么做。没有反应速度失败惩罚，没有新增体力池或现实日期锁。

| 本次状况 | A：暖心茶点，在小屋小圆桌 | B：花园小聚，在树荫下临时茶布 | 两方案一阶材料价值 |
|---|---|---|---:|
| 晴日来坐坐 | 茶Lv3 + 烘焙Lv3 | 茶Lv2 + 园艺Lv3 + 手作Lv2 | 各8 |
| 想留一份纪念 | 茶Lv3 + 烘焙Lv2 + 手作Lv2 | 茶Lv2 + 园艺Lv2 + 手作Lv3 | 各8 |
| 今天有点风 | 茶Lv3 + 烘焙Lv2 + 工具Lv2 | 茶Lv2 + 园艺Lv2 + 手作Lv2 + 工具Lv2 | 各8 |

各物品数量均为1，等级与原物品表一致。暖心茶点更依赖茶和烘焙，花园小聚增加园艺与手作，玩家可结合已有库存和想看到的结果选择。价值相近用于控制负担差异，不等同真实耗时完全相同。

交付前可换方案，不扣材料、不增加一套茶会库存。确认时沿用棋盘和仓库的精确阶数交付，整单一次扣物。临时茶布、道具和座位不解锁尚未完成的主线家具，茶会结束后撤下；永久纪念物进入独立小槽位。

两方案必须兑现以下区别：场地与坐位、准备物摆法、至少一段两熊动作、具体回应、对应纪念物的配色/展示样式。相同金币收益下，结果由玩家想要的生活决定。小栗加入前回应由两熊彼此完成，加入后补入来客的接杯和反馈，配方框架不另造一套。

重复完成奖励采用与同材料价值邻里委托一致的金币、体力和经验规则；价值8对应每轮基础奖励28金币、3体力、12经验，无心愿星。纪念物及款式仅首次解锁。经验升级额外奖励沿用原规则。正常模式与轻松模式使用同一套选择和事件，轻松模式继续绕过生产体力与库存限制。

提交校验预期轮次和方案，旧请求拒绝；成功交付统一记录扣物、奖励、纪念物、轮次加一和本次展示上下文，立即保存，再播放演出。重载时恢复本次结果，可补看演出；跳过、重看、动画中断或照片导出都不会再扣物或发奖。规则拥有真实结果，动画只呈现结果。

成功完成茶会沿用整单交付口径，`stats.order` 与 `daily.order` 各增加1；末章中间准备不增加，最后整单完成才增加。每日订单说明同步为“完成3张主线、邻里或茶会订单”，目标与每日奖励保持原值。茶会基础奖励与整单计数参考当前规则：[engine.mjs](<E:/Desktop/布布一二：好日子小屋/bubu-yier-cozy-home-v1.1/src/engine.mjs:144>)。

**两熊具体动作的最低内容要求。**

| 场面 | 玩家参与 | 必须看得见的动作与后果 |
|---|---|---|
| 端茶摆杯 | 依次点摆杯位置与端茶角色 | 一二走到桌边放杯，布布持壶移动，壶与杯在对应位置交接/倒茶 |
| 扶苗浇水 | 先让一二扶稳，再让布布浇水 | 身体与手部姿势变化，水壶跟随持握位置，水滴落到实际幼苗处 |
| 风吹茶巾 | 选择先压稳或先固定一角，点对应动作 | 茶巾/夹子实际移动，两熊接续操作，完成后茶巾位置与状态改变 |
| 迎接小栗 | 点入口迎接，再点准备好的座位 | 小栗从入口移动到座位，两熊让位、递杯，小栗接住并回应 |

单段目标约3—6秒，属于设计目标；最终按实播手感调整。角色动作帧、位移与道具持握共同构成演出。只换站姿、飘粒子或轮播静态图不能算上述动作完成。演出可跳过与重看；减少动画时用清楚的前后动作关键帧和道具结果，奖励与进度相同。

|---|---|---|---|
| 晴日来坐坐 | 两熊选的杯垫 | 小屋茶桌旁 | 两方案各有可解锁配色/摆法；收藏不因换装丢失 |
| 想留一份纪念 | 手绘小卡 | 庭院留言位 | 通关前由两熊互赠，小栗来访后回应本次准备 |
| 今天有点风 | 小风铃 | 花园枝旁 | 记录本次一起固定茶巾、听风的回忆 |

仅新增三个可替换位置。装备与收藏分别存储，玩家随时更换已解锁款式，不花第二套货币；永久物件可点击重看对应事件。作为后续经营方向，金币购买更多可选美化留待本循环验证后，v1.2继续把金币用于既有便利系统。

每个已取得纪念物款式保存首次取得时的事件键、参与者与必要展示参数，最多六份固定记录。永久物件回放读取自己的首次记录；`tea.lastResult` 只负责最近一次结果续看与合照。后续重玩不覆盖首次纪念，也不重发解锁奖励。

全景不重绘多套整幅背景。用现有素材和少量覆盖层，各区体现一个实际阶段变化：小屋的欢迎小物、花园的幼苗/纪念风铃、庭院的旗与来客留言。覆盖层必须从真实进度和装备推导，背景自带的环境花草不冒充玩家新装修。近景、全景、回忆和照片共用同一展示描述。

**F08—F12：把已有页面做成可靠、可读的完整体验。**

- 回放使用只读展示上下文。开场固定为序章、空小屋；任务回放使用任务自己的章号、区域及完成后的装修范围。历史存档没有保存当时配色，使用当前配色并如实说明，不能宣称精确还原历史。回放不改变进度、物品和货币。
- 第五章回忆卡和弹层固定夜景与正确休息人物。关键惊讶、害羞对白使用明确资源映射；先复用已有表情文件，确实缺少合适图时再补入清单。
- 引导条、提示按钮、订单面板、小铺统一读取当前目标。提示使用屏幕上的按钮名称；在主线、邻里和茶会切换时，不能保留另一目标的“已备齐”描述。
- 弹层重绘后按稳定控件标识恢复焦点，遮罩下的页面暂停获得键盘焦点；关闭回到原入口。启动页与剧情页也遵守同一规则。保留Escape、Tab和已有快捷操作。
- 常用详情动作与关闭/返回/来源跳转按钮的命中区以约44×44 CSS px为设计目标，关键辅助文字以约12px为目标。7×7棋盘按实际可用宽度独立布局，不能机械地把所有格子强改为44px。狭窄详情栏优先保留收纳与撤销，出售和拆分放进可读面板，避免相邻命中区重叠。
- 在真实小屏棋盘查看工作台与高阶集合物的轮廓、等级、库存。只有现场辨识确实不足时才局部返修该素材；保持已确定的色彩和体积方向。全装修场景检查家具层级、人物占地和活动路线，局部调坐标而不改规则。
- 声音继续区分点击、合成、交付与动作反馈。新长演出控制重复提示音密度，音乐默认关闭，切后台按设置暂停。增加实际试听记录，不以存在WAV文件或无异常代替听感验收。
- 照片点击时冻结区域、昼夜、姿势、配色、装备和来客/道具位置，再异步取图。普通家园合照与“这次茶会合照”采用各自场景上下文，后者实际包含参与者及所选方案；不能都返回原聚会图。
- 自动保存、备份、导入确认、切后台保存与导出继续沿用。新结果在记录后立即保存，保存失败给出清楚反馈和导出入口。原生关闭重开、JSON和PNG实际落盘属于现场验收。

**F13：先量首开，再决定资源优化。**

已知v1.1运行资源约37.04MiB，离线单文件约49.56MiB，启动等待所有运行图片。这是包体事实，当前没有加载速度和掉帧实测。

实施前记录同一入口、同一设备/网络下“打开→可点开始”“开始→首个棋盘可操作”的时间、首屏资源量与可见缺图。优化后按同一口径比较；普通受控前后测量即可，不做压力测试或完整设备矩阵。

优先将启动页和当前交互页的必要资源与晚期场景分开预载，进入后续页面时保证其素材就绪。静态站缓存准备与可以开始玩分开显示。单文件继续完整内嵌全部素材，分批解码只能减少同时启动的负担，不能称为减少该HTML的传输体积。

只有实际测量显示运行图尺寸或格式成为瓶颈，才制作运行适配版本；源原件和参考卡保留，美术变更遵守原生生图/返修流程。报告必须给出实际改善，或明确没有测得改善。浏览器权限仍不可用时，性能和运行页验收保留为未完成，不用规则模拟补出加载秒数。

**素材与内容清单：把成本锁在小范围内。**

| 素材包 | 本版必要内容 | 复用与制作要求 |
|---|---|---|
| 原创来客 | 小栗角色卡、行走/招手/坐下/接杯关键帧，目标约7帧 | 身份与色板在制作前形成角色卡，不借用官方配角身份 |
| 两熊动作 | 每只行走4帧、接递3帧、俯身支扶2帧，目标共18帧 | 组合用于端茶、浇水、夹茶巾和迎客；全部保持角色卡特征 |
| 活动道具 | 水壶、夹子、临时茶布/铺垫及必要持握道具 | 茶壶、杯子、面包等尽量复用现有图集；临时道具与主线家具ID分开 |
| 永久小物 | 杯垫、手绘卡、小风铃三类 | 两方案优先通过可见配色/摆法差异复用，不要求六套大图 |
| 表情 | 关键惊讶、害羞、休息映射 | 先使用已有合适原图，缺项才新增 |
| 地图变化 | 三处少量覆盖物 | 复用装修/纪念物源图，不生成三套完整地图 |
| 故事文字 | 第21—24项精修、首访回信、六组茶会结果、日常阶段文案 | 保留已有前20项事实及蛋糕/纸鲸/雏菊回扣，不扩成无限分支 |
| 声音 | 现有音效和音乐为主体 | 新增只覆盖实际交接/放置反馈，听感决定是否必要 |

动作帧数量是制作目标，最后按实际可连续播放的动作验收，不能靠凑帧数算完成。所有包含布布或一二的生成/返修图都同时带入两张权威角色卡；有小栗时同时带入小栗卡。程序负责图集取槽、播放、位移、层级和道具锚点，不程序重绘角色原图。生成后做原图与运行场景两次视觉检查。

先制作并接入一段“两熊端茶摆杯”，通过身份一致性、移动和道具交接验收后，再批量生产剩余动作。主要内容工作量是角色动作和演出编排，应记录每个素材包与事件的实际工时，不把它估成几句文案修改。

**七日反馈检查点与后续收敛。**

先用5—8名目标玩家作界面与动作定性观察，修清楚的新手障碍；随后用同一来源的一小批真实玩家观察七日，记录实际人数、版本与失访情况，不预设商业留存达标值。

分别观察首次进入后的D1/D7、到达茶会解锁的比例，以及从茶会解锁起的再次游玩。没有走到茶会的玩家不能算已经测试了茶会留存；解锁后的回访也不能混成全体D7。D30需要实际等待并记录，不能用七日或规则模拟外推。

关注玩家能否解释自己的方案、是否主动改方案、领完奖励后是否继续看家园/换摆法、三类纪念物收齐后是否仍愿重办，以及来客约定是否形成期待。允许中断、跳天与正常回归，试验不额外添加连续登录大奖干扰判断。

同一轮记录内容制作工时：一段对白、一件小物、一套动作及接入时间。若玩家确实愿重玩且内容供给可持续，下一轮再扩一个生活主题或更多可选美化；若主要只为新奖励回来，先改选择与反馈。v1.2的完成是闭环可玩并获得反馈，90日留存仍需后续实证。
